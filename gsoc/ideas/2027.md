# GSoC 2027 Project Ideas

Every idea below builds on code that is live today. Most land in [`learn/`](https://github.com/alphaonelabs/website/tree/main/learn), the platform behind [learn.alphaonelabs.com](https://learn.alphaonelabs.com), which runs on Cloudflare Workers (Python), D1, Durable Objects and R2. The rest grow one of the sibling projects in the [monorepo](https://github.com/alphaonelabs/website).

These are starting points, not specs. Strong proposals reshape them, combine them, or pitch something new entirely.

---

## 1. Live Classrooms with Real Audio, Video and Captions

**Project:** `learn/` + `voxbridge/` · **Size:** 350 hours · **Difficulty:** Hard · **Mentors:** TBA

### Abstract
learn's virtual classroom already has seats, presence, chat and a shared whiteboard, all running on Durable Objects. What it lacks is the thing that makes a class a class: hearing and seeing each other. This project adds real-time audio and video through Cloudflare Realtime (SFU), with live captions powered by VoxBridge so every session is accessible from day one.

### Tasks
- Add WebRTC audio/video through Cloudflare Realtime, with signaling through the existing `ClassroomDO`.
- Instructor controls: mute all, spotlight, hand-raise queue, and breakout rooms backed by separate Durable Objects.
- Live captions and transcripts using VoxBridge speech-to-text, saved to the session record.
- Graceful degradation: audio-only and captions-only modes for slow connections.

### Expected Outcomes
- Teachers can run a full live class on learn.alphaonelabs.com without a third-party video tool.
- Every session produces a searchable, captioned transcript.

### Skills
WebRTC, JavaScript, Python, Durable Objects, speech-to-text basics.

## 2. Course-Grounded AI Tutor with Teacher Controls

**Project:** `learn/` + `learnpilot/` · **Size:** 350 hours · **Difficulty:** Hard · **Mentors:** TBA

### Abstract
Generic chatbots answer from the whole internet and happily do students' homework. This project builds a tutor that answers **only from a course's own materials**, cites the page it used, and follows rules the teacher sets ("give hints, never final answers"). It brings the LearnPilot idea to life inside learn, using Workers AI and Vectorize for retrieval.

### Tasks
- Index activity materials, session notes and quiz explanations into Vectorize, per activity.
- Tutor chat with source citations and a "show me where this came from" view.
- Teacher policy panel: hint-only mode, topics to refuse, daily limits, and a review log.
- Evaluation set measuring answer accuracy and refusal behaviour for each policy.

### Expected Outcomes
- A tutor teachers trust enough to turn on, because they control it.
- A reusable retrieval layer other learn features can query.

### Skills
Python, LLMs and retrieval (RAG), prompt evaluation, Workers AI / Vectorize.

## 3. Offline-First Learning for Low-Connectivity Regions

**Project:** `learn/` · **Size:** 175 hours · **Difficulty:** Medium · **Mentors:** TBA

### Abstract
Many learners we want to reach have expensive or unreliable internet. This project turns learn into an installable Progressive Web App that keeps working offline: downloaded lessons, quizzes you can take on a bus, and progress that syncs when you reconnect.

### Tasks
- Service worker with a cache strategy for activity pages, materials and quizzes.
- An offline queue for quiz attempts and progress, with conflict-safe sync to D1.
- "Download for offline" per activity, plus a storage manager.
- Lite mode: compressed images and no autoplay media on slow connections.

### Expected Outcomes
- A learner can download a course on Wi-Fi and complete it without a connection.
- Measurably lower data usage per lesson.

### Skills
JavaScript, Service Workers, IndexedDB, Python.

## 4. Verifiable Certificates with Open Badges 3.0

**Project:** `learn/` · **Size:** 175 hours · **Difficulty:** Medium · **Mentors:** TBA

### Abstract
learn already issues certificates, but a PDF is easy to fake and hard for employers to check. This project issues certificates as **Open Badges 3.0 / W3C Verifiable Credentials**: cryptographically signed, portable to LinkedIn and digital wallets, and verifiable by anyone at a public URL without contacting us.

### Tasks
- Signing keys stored as Worker secrets, with a documented key-rotation process.
- Issue OB 3.0 credentials when a learner completes an activity, alongside the existing certificate row.
- A public verification page and JSON-LD endpoint for each credential.
- Revocation list support and a learner "credentials wallet" page.

### Expected Outcomes
- Every certificate can be verified independently and cannot be forged.
- Learners can share achievements anywhere that accepts Open Badges.

### Skills
Python, public-key cryptography, JSON-LD, web standards.

## 5. Bring Your Course: Common Cartridge and LTI 1.3 Interoperability

**Project:** `learn/` · **Size:** 350 hours · **Difficulty:** Hard · **Mentors:** TBA

### Abstract
Teachers won't rebuild years of material by hand. This project lets them import courses from Moodle, Canvas and other platforms using IMS **Common Cartridge**, and lets learn activities run inside those platforms as an **LTI 1.3** tool. That makes learn something schools can adopt alongside their existing systems.

### Tasks
- Common Cartridge import: modules, pages, files (to R2) and QTI quizzes (to learn's quiz tables).
- Common Cartridge export, so teachers are never locked in.
- An LTI 1.3 tool provider with OIDC launch, deep linking, and grade passback.
- Tested against Moodle and Canvas sandbox instances.

### Expected Outcomes
- A teacher can move a real course into learn in minutes.
- Schools can embed learn activities in the LMS they already use.

### Skills
Python, OAuth 2.0 / OIDC, XML, LMS standards.

## 6. Privacy Center: Encryption Keys, Data Export and Account Deletion

**Project:** `learn/` · **Size:** 175 hours · **Difficulty:** Medium · **Mentors:** TBA

### Abstract
learn encrypts personal data at rest. The next step is giving users visible control over it. This project builds a Privacy Center: export everything we hold about you, delete your account properly (including derived data), see who can see what, and rotate the platform's encryption keys without downtime.

### Tasks
- A self-service data export (JSON plus files from R2) and verified account deletion that cascades through every table.
- Zero-downtime encryption key rotation: re-encrypt rows in batches with dual-key reads.
- A per-field visibility view ("teachers in this activity can see your name").
- A written threat model and a security regression test suite in CI.

### Expected Outcomes
- GDPR-style rights users can exercise without emailing anyone.
- Key rotation becomes a routine, tested operation.

### Skills
Python, applied cryptography, SQL, security testing.

## 7. One Learn, Many Languages

**Project:** `learn/` · **Size:** 175 hours · **Difficulty:** Medium · **Mentors:** TBA

### Abstract
learn already routes `/en`, `/es`, `/fr`, `/de` and `/zh`, but most of the interface and nearly all course content are English-only. This project builds a proper translation pipeline: extract UI strings, machine-translate drafts with Workers AI, and let bilingual community members review them before they ship. Teachers can offer their activities in several languages too.

### Tasks
- Extract every UI string into message catalogs, with plural and right-to-left support.
- A community review workflow: AI draft, then a human approves before it goes live.
- Per-activity translations of titles, descriptions and quiz content.
- Language detection and switching that respect user preference.

### Expected Outcomes
- learn fully usable in at least five languages, with a sustainable way to add more.

### Skills
JavaScript, Python, i18n, UX writing.

## 8. QuantaLab Experiments as Graded Assignments

**Project:** `quantalab/` + `learn/` · **Size:** 175 hours · **Difficulty:** Medium · **Mentors:** TBA

### Abstract
QuantaLab's simulations are fun to explore, but teachers can't assign them, and students' work disappears when the tab closes. This project makes experiments embeddable in learn activities as assignments: students run the simulation, record observations, submit a lab report, and get feedback (partly automated, partly from the teacher).

### Tasks
- An embed protocol (`postMessage`) between QuantaLab and learn, with saved experiment state.
- A structured lab-report template with auto-checked measurements against expected ranges.
- A teacher grading view, connected to learn's progress and certificates.
- At least five complete, curriculum-aligned experiments.

### Expected Outcomes
- Teachers assign a virtual lab as easily as a quiz.

### Skills
JavaScript, physics or chemistry fundamentals, Python.

## 9. A Shared Virtual Campus

**Project:** `virtual/` + `learn/` · **Size:** 350 hours · **Difficulty:** Hard · **Mentors:** TBA

### Abstract
[virtual.alphaonelabs.com](https://virtual.alphaonelabs.com) is a three.js world you currently explore alone. This project makes it a living campus: learners see each other, walk into a building to join a learn classroom, and meet classmates between sessions. Presence and movement sync through Durable Objects, the same infrastructure learn's classroom already uses.

### Tasks
- Multiplayer presence and movement through a Durable Object per world region.
- Sign in with your learn account; avatars and display names come from learn profiles.
- Portals that open a live learn session, with seating handed off to the classroom.
- Performance budget: smooth on a mid-range phone, with level-of-detail and culling.

### Expected Outcomes
- A campus that makes online learning feel social, connected to real classes.

### Skills
TypeScript, three.js, WebSockets, networking.

## 10. Citizen-Science Air Quality Network

**Project:** `earthmind/` · **Size:** 175 hours · **Difficulty:** Medium · **Mentors:** TBA

### Abstract
EarthMind can ingest readings, detect anomalies and spot trends, but it has no data. This project connects it to the real world: schools and volunteers attach low-cost air-quality sensors, publish readings to EarthMind, and use the results in class. It combines open hardware, open data and real science education.

### Tasks
- A device ingestion API with per-device keys, rate limits and data validation.
- Import from public sources (OpenAQ) to fill gaps and calibrate readings.
- A public map and per-classroom dashboards, with anomaly alerts.
- A classroom kit guide: a parts list under $40, firmware, and a lesson plan.

### Expected Outcomes
- Real air-quality data from participating schools, open to everyone.

### Skills
Python, data analysis, IoT basics, mapping.

Good first GSoC projects. Each one is also a great way to earn your five merged PRs.

- **Make learn's test suite green.** About 30 tests fail on `main` because they weren't updated after code changes. Fix them, then make the suite required in CI.

- **BotLab block coding.** Add a Blockly editor that compiles to BotLab's robot commands, with a path to "show me the Python".
- **Mockuper templates.** A template gallery and export to PNG and SVG.
